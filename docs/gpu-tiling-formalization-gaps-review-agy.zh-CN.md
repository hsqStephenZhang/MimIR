# 结论

1. **三项优先核实的“（评审）”条目全部属实，且代码里的实际漏洞比两份文档和 Codex 评审指出的更深：**
   - **流水深度未限制到硬件/PTX 范围（属实）**：[`lower_to_mem.cpp:2293`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/phase/lower_to_mem.cpp#L2293) 仅取 `depth = min(pipeline, literal_count)`，[`nvptx.cpp:774-777`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/nvptx/phase/nvptx.cpp#L774-L777) 直接把 `ring.size() - 2` 格式化为 `@llvm.nvvm.cp.async.wait.group(i32 {})` 立即数。更严重的是，[`nvptx.cpp:696-708`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/nvptx/phase/nvptx.cpp#L696-L708) 在非 4/8/16B 或非直接 global load（如带越界分支的 `stage_read_impl`）时会将 `gpu.store_async` **静默退化为同步 `store`**，使异步组内实际拷贝数与 `wait_group` 失配并在槽位尚未消费完时提前覆写。
   - **`Levels::mma` 不核实乘加与访问映射（属实，可构造端到端错算反例）**：[`tile_fuse.cpp:1569-1594`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/phase/tile_fuse.cpp#L1569-L1594) 与 [`lower_to_mem.cpp:2054-2138`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/phase/lower_to_mem.cpp#L2054-L2138) 从未检查 `mr.comb`。将 [`lit/gpu/tile_mma.mim:19-21`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/lit/gpu/tile_mma.mim#L19-L21) 的 `mac` 改成 `acc + (x - y)` 后，因 `warp_red`（`bind = 0, loop == ro`）在 [`tile_fuse.cpp:1493-1499`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/phase/tile_fuse.cpp#L1493-L1499) 跳过 `reduction_law` 检查，请求会一路通过 `TileFuse` 并被 `lower_mma`（[`:2134`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/phase/lower_to_mem.cpp#L2134)）无条件编译成 `gpu.mma_tf32`（算成矩阵乘加）。此外，当 `K == 8` 且 `warp_red` 块长也为 `8` 时，[`tile_fuse.cpp:1483`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/phase/tile_fuse.cpp#L1483) 跳过 `tile_fold`，导致 [`lower_to_mem.cpp:1311-1313`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/phase/lower_to_mem.cpp#L1311-L1313) 因 `fragments_` 为空而**静默丢弃 `tensor.mma`**。
   - **`Fill::contiguous` 只查前 64 个位置不够（属实，且存在维度语义错位 bug）**：[`panel_layout.cpp:124-132`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/phase/panel_layout.cpp#L124-L132) 只查 `l < min(total, 64)`。在 [`panel::decode`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/phase/panel_layout.cpp#L427) 下，既可构造第 0 行 64 个向量对齐、第 1 行（`l = 64`）因奇数 pad 失齐的合法 `layout_expr`，也可构造 `shift = 6` 使前 64 行 `group = 0`、第 64 行起 `group = 1` 拆断向量的 swizzle。更致命的是，`Fill::contiguous` 查的是**一维线性偏移连续**，而 [`lower_generate`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/phase/lower_to_mem.cpp#L888-L894) 却直接对 `storage` **最后一维**做 `storage.back() / vec` 向量化：当 3D 面板末维 `tile == 1`（如 `1×1` 线程 tile）且 `inner = 1` 时，一维偏移连续但 `storage.back() == 1`，`lower_generate` 会算出 `runs.back() = 1 / 4 = 0`。

2. **“三类义务”框架方向正确，但第二份文档把多项跨线程/全局不动点性质错塞进了第 1 类（局部 `assert`）和第 2 类（受限构造子）。**
3. **A/B/C 方案中，B2 仅拆成“同步 collective”与“异步传输”仍不够**（缺 work-group vs. warp 多粒度作用域、槽位复用的跨超步 WAR 借用令牌、以及 `staged`/`chained` 多面板共用单栅栏的建模）。
4. **从“尽可能减少 C++”的目标看，第二份文档抓错了重点**：A1–A5 全部做完最多触及约 300 行 C++，却放过了真正占大头且最契合论文第 7 节 `Tileable` 思想的两块 C++——[`normalizers.cpp:336-507`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/normalizers.cpp#L336-L507) 的算子切片归一化（`tile_of_*` / `producer_tile`）和 [`lower_to_mem.cpp`](file:///workspaces/compile/MimIR/.worktrees/gpu-tiling/src/mim/plug/tensor/phase/lower_to_mem.cpp) 中用 C++ `World` API 手工拼装 Mim 函数的数百行样板代码。
